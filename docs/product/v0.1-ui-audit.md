# v0.1 UI Audit — All Pages

## 1. Dropdown Clipping & z-Index Issues

### Problem
Page toolbars are inside `overflow-hidden` containers, which clip `.dropdown` menus when they expand downward.

### Location
| Page | File | Line | Container |
|------|------|------|-----------|
| Logs | `pages/Logs.tsx` | 109 | `overflow-hidden` on the content area |
| Errors | `pages/Errors.tsx` | 110 | `overflow-hidden` on the content area |
| Services | `pages/Services.tsx` | 97 | `overflow-hidden` on the content area |

### Affected Dropdowns
- **Services row (toolbar)**: Service selector, Auto refresh, Time range
- **Logs toolbar**: Service selector, Auto refresh, Time range
- **Errors toolbar**: Service selector, Auto refresh, Time range
- **Table toolbar**: Limit selector in all 3 tables

### Fix
Replace `overflow-hidden` with `overflow-visible` on the toolbar container, or move the Dropdown portal outside the clipping parent. The Dropdown component already uses `z-[100]` — the issue is the parent `overflow: hidden` not the z-index.

```diff
- <div className="flex-1 flex flex-col min-w-0 overflow-hidden">
+ <div className="flex-1 flex flex-col min-w-0">
```

## 4. Table Overflow Scroll — Missing Left Border

### Problem
The table's outer container has `border` (uniform border), but when the table content is wider than the container and horizontal scrolling occurs, the sticky table header and body rows have no visual border on their **left edge** — only `border-r` between columns.

The outer `border` on the wrapping div creates a boundary, but the inner scroll area's first column (the "View" button column) only has `border-r` on its right edge — no `border-l`. When scrolling, the sticky header appears flush against the container's left edge with no visible separation.

### Fix
Add `border-l` to the "View" column cell in both header and body rows, or add a `border-l` on the first child of the scroll container.

**Files:**
- `components/LogsTable.tsx:114,158`
- `components/ErrorsTable.tsx:112,155`
- `components/ServicesTable.tsx:124,166`

```diff
- <div className="w-[60px] shrink-0 h-full border-r">
+ <div className="w-[60px] shrink-0 h-full border-r border-l">
```

## 5. Table Sorting — No Effect

### Problem
Clicking column headers calls `handleSort()` which updates `sortColumn` and `sortDirection` state, but the mock data is never sorted. The chevron icon changes but rows stay in their original order.

### Files Affected
- `components/LogsTable.tsx:60-70`
- `components/ErrorsTable.tsx:58-68`
- `components/ServicesTable.tsx:70-80`

### Fix
Apply sorting to the data array before passing it to the virtualizer:

```tsx
const sortedData = useMemo(() => {
  if (!sortColumn) return mockData
  return [...mockData].sort((a, b) => {
    const aVal = a[sortColumn as keyof typeof a]
    const bVal = b[sortColumn as keyof typeof b]
    const cmp = String(aVal).localeCompare(String(bVal), undefined, { numeric: true })
    return sortDirection === 'asc' ? cmp : -cmp
  })
}, [sortColumn, sortDirection])
```

Then use `sortedData` instead of `mockData` in the virtualizer.

## 6. Sidebar Filters — No Effect ✅ Fixed

### Problem (fixed)
All three filter sidebars updated `checked` state when checkboxes were toggled, but `checked` was a flat `{id: boolean}` map that never propagated to the query predicate — no filtering occurred except for services.

### Files Affected
- `components/FilterSidebar.tsx` (shared by Logs, Errors, Services — the per-page `ErrorsFilterSidebar.tsx` / `ServicesFilterSidebar.tsx` copies were removed)

### Fix (implemented)
- `FilterState.checked` is now section-aware: `?ch=` stores `{"section_id": ["item", ...]}`, written via `toggleChecked(sectionId, id)` in `useFilterState.ts`.
- New `compileCheckedToQuery()` folds checked sections into the SQL WHERE clause (`level IN (...)`, `line IN (...)`, response-status ranges, `exception_type IN (...)`, `service IN (...)`), so the histogram chart and table update together from the same predicate.
- Checked state is keyed by section id rather than the current item list, so a checked value is not silently dropped when a section temporarily has zero rows.
- The sidebar also gained: `localStorage`-persisted collapse state, a "No data" empty state that keeps the section header visible, and skeleton loading while counts fetch.

## 9. Limit Dropdown — No Effect

### Problem
The limit dropdown changes state (e.g., `'500'`, `'1k'`) but the virtualizer always shows all rows.

### Files
- `components/LogsTable.tsx:46,47`
- `components/ErrorsTable.tsx:44,45`
- `components/ServicesTable.tsx:56,57`

### Fix
Pass the limit value or parse and slice accordingly:

```tsx
const parsedLimit = limit === 'All' ? mockData.length : parseInt(limit.replace('k', '000'))
const displayData = sortedData.slice(0, parsedLimit)
```

Then use `displayData.length` in the virtualizer count.
