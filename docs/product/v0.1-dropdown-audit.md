# v0.1 Dropdown Audit — Alignment Issues & Fixes

Every chart dropdown was evaluated for whether its options semantically match the chart's data type.

---

## Logs Page (`/logs`)

### Chart 1: Total Requests (LogVolumeChart)

| Chart Type | Current Dropdown Options | Issue |
|-----------|------------------------|-------|
| Requests over time (line chart) | Count, Rate, Avg, **P95**, **P99** | ❌ P95/P99 are latency percentiles — meaningless for request volume |

**Should be:** `Count | Rate` only

---

### Chart 2: Errors (ErrorsChart)

| Chart Type | Current Dropdown Options | Issue |
|-----------|------------------------|-------|
| Error count over time (bar chart) | Count, Rate, Avg, **P95**, **P99** | ❌ P95/P99 are latency concepts — meaningless for error count |

**Should be:** `Count | Rate` only

---

### Chart 3: Status Codes (StatusCodesChart)

| Chart Type | Current Dropdown Options | Issue |
|-----------|------------------------|-------|
| Status code distribution (pie/donut) | Count, Rate, Avg, **P95**, **P99** | ❌ P95/P99 don't apply to status code distribution. Avg is also questionable — average of status codes has no useful meaning |

**Should be:** `Count | Rate` only

---

### Group By Dropdown (shared across all 3 charts)

| Current Options | Issue |
|----------------|-------|
| nothing, service, level, status_code | ✅ Valid for Requests & Errors charts. ⚠️ For Status Codes chart, grouping by `status_code` is redundant — the chart already IS status codes |

**Should be per-chart:**
- **Requests:** `nothing | service | level`
- **Errors:** `nothing | service | level | status_code`
- **Status Codes:** `nothing | service | level` (remove `status_code` — already the chart subject)

---

## Errors Page (`/errors`)

### Chart 1: Error Count (ErrorCountChart)

| Chart Type | Current Dropdown Options | Issue |
|-----------|------------------------|-------|
| Error count over time (bar chart) | Count, Rate, Avg, **P95**, **P99** | ❌ Same issue as Logs — P95/P99 irrelevant to counting errors |

**Should be:** `Count | Rate` only

---

### Chart 2: Error Rate (ErrorRateChart)

| Chart Type | Current Dropdown Options | Issue |
|-----------|------------------------|-------|
| Error rate over time (line chart) | Count, Rate, Avg, **P95**, **P99** | ❌ P95/P99 are meaningless for rate. Rate-of-rate (Rate option) is confusing |

**Should be:** `Count | Rate (as %)` only

---

### Chart 3: Errors by Service (ErrorByServiceChart)

| Chart Type | Current Dropdown Options | Issue |
|-----------|------------------------|-------|
| Errors grouped by service (pie chart) | Count, Rate, Avg, **P95**, **P99** | ❌ P95/P99 irrelevant. Group-by-service is already the chart identity |

**Should be:** `Count | Rate` only

---

### Group By Dropdown (shared across all 3 charts)

| Current Options | Issue |
|----------------|-------|
| nothing, service, level, status_code | ❌ For "Errors by Service" chart, grouping by `service` is the chart's entire identity — it's self-referential |

**Should be per-chart:**
- **Error Count:** `nothing | service | level | status_code`
- **Error Rate:** `nothing | service | level | status_code`
- **Errors by Service:** `nothing | level | status_code` (remove `service` — chart already IS errors by service)

---

## Analytics Page (`/analytics`)

### Chart: Log Ingestion Over Time

| Chart Type | Current Options | Issue |
|-----------|----------------|-------|
| Log volume over time (bar chart) | Sum, Rate, Volume | ✅ All valid — Sum & Volume are similar but acceptable |

**Verdict:** ✅ Good

---

### Chart: Error Rate Over Time

| Chart Type | Current Options | Issue |
|-----------|----------------|-------|
| Error rate over time (line chart) | Sum, Average, Count, Rate | ⚠️ `Sum` — summing error rates is meaningless. `Count` overlaps with Sum. `Average of error rate` is confusing |

**Should be:** `Rate | Count` only

---

### Chart: Latency Percentiles

| Chart Type | Current Options | Issue |
|-----------|----------------|-------|
| P50/P90/P99 multi-line chart | P50,P90,P99, P50, P90, P99, Average | ✅ All latency-appropriate options |

**Verdict:** ✅ Good (though "Average" as percentile view is slightly odd — keep for flexibility)

---

### Chart: Status Codes (StatusCodesPieChart)

| Chart Type | Current Options | Issue |
|-----------|----------------|-------|
| Status code distribution (pie chart) | Sum, Average, Count, Rate | ❌ `Average of status codes` is semantically meaningless (what is average status code 342?). `Sum` of status codes is also meaningless |

**Should be:** `Count | Rate` only

---

### Chart: Top Noisy Services

| Chart Type | Current Options | Issue |
|-----------|----------------|-------|
| Services ranked by volume (bar chart) | Logs Generated, Errors, Latency | ✅ All valid sort criteria |

**Verdict:** ✅ Good

## Table Dropdowns

### LogsTable / ErrorsTable: Limit

| Options | Issue |
|---------|-------|
| 500, 1k, 5k, 10k | ✅ Standard pagination limits |

**Verdict:** ✅ Good

---

### LogsTable / ErrorsTable: Views

| Options | Issue |
|---------|-------|
| Compact, Default, Detailed | ⚠️ None of these render differently — they're stored in state but unused |

**Should be:** Either implement the view modes or remove the dropdown until v0.2. For v0.1, remove it to avoid dead UI.

---

## Summary: All Issues

| Page | Chart | Problematic Options | Fix |
|------|-------|-------------------|-----|
| Logs | Total Requests | P95, P99 | Remove, keep Count, Rate |
| Logs | Errors | P95, P99 | Remove, keep Count, Rate |
| Logs | Status Codes | P95, P99, Avg | Remove, keep Count, Rate |
| Logs | Status Codes Group By | status_code | Remove (redundant) |
| Errors | Error Count | P95, P99 | Remove, keep Count, Rate |
| Errors | Error Rate | P95, P99 | Remove, keep Count, Rate |
| Errors | Errors by Service | P95, P99 | Remove, keep Count, Rate |
| Errors | Errors by Service Group By | service | Remove (self-referential) |
| Analytics | Error Rate Over Time | Sum, Average | Remove, keep Rate, Count |
| Analytics | Status Codes | Sum, Average | Remove, keep Count, Rate |
| Both tables | Views dropdown | All | Remove or wire up rendering |

**Fix approach:** Create per-chart metric option arrays instead of sharing a single `chartMetrics` array across all charts. Each chart type gets only semantically valid options.
