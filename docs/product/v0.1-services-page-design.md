# v0.1 Services Page — Product Design

## Page Purpose

The Services page gives devs a per-service health dashboard. Unlike Analytics (which shows aggregate cluster-wide metrics), Services is about **individual service status, health trends, and quick triage**. The existing analytics `ServiceHealthChart` shows a 30,000ft view — this page is the drill-down.

## Section 1: Service Health Cards (top row)

Four cards in a row, one per service. Each card shows:

| Element | Description | Example |
|---------|-------------|---------|
| Service name | Bold label | `api` |
| Health dot | Color-coded circle | 🟢 Healthy / 🟡 Degraded / 🔴 Down |
| Uptime % | Percentage over selected window | `99.8%` |
| Request count | Total requests in window | `1.2M` |
| Mini sparkline | Request volume trend (reuse `AnalyticsMetricCard` pattern) | line chart |

**Health status thresholds:**
- **Healthy** — error rate < 1%, latency P95 < 100ms, uptime > 99%
- **Degraded** — error rate 1-5%, latency P95 100-500ms, uptime 90-99%
- **Down** — error rate > 5%, latency P95 > 500ms, uptime < 90%

## Section 2: Chart Row (3 side-by-side)

Reuse existing `AnalyticsChartPanel` wrapper pattern.

### Chart 1: Requests by Service
- **Type:** Horizontal bar chart (reuse `NoisyServicesChart` pattern)
- **X-axis:** Request count
- **Y-axis:** Service name
- **Color:** Blue, with bar colored by health status
- **Dropdown:** Metric — `Count | Rate`

### Chart 2: Error Rate by Service
- **Type:** Horizontal bar chart
- **X-axis:** Error rate %
- **Y-axis:** Service name
- **Color:** Red gradient (higher = darker)
- **Dropdown:** Metric — `Count | Rate`

### Chart 3: Avg Latency by Service
- **Type:** Horizontal bar chart
- **X-axis:** Latency in ms
- **Y-axis:** Service name
- **Color:** Amber gradient (higher = darker)
- **Dropdown:** Metric — `Avg | P50 | P95 | P99`

## Service Health Chart Type

The existing analytics `ServiceHealthChart` uses a **stacked horizontal bar** showing Healthy/Degraded/Down hours per service. This is the right chart type for the aggregate view.

For the **Services page**, add a **per-service health timeline** (in the drawer):

```
Service Health Over Time
─────────────────────────
 🟢 🟢 🟢 🟡 🟢 🟢 🟢 🟢 🟡 🟢 🟢 🟢  api
 🟢 🟢 🟢 🟢 🟢 🟡 🟡 🔴 🟡 🟢 🟢 🟢  web
 🟢 🟡 🔴 🟡 🟡 🟡 🟢 🟢 🟢 🟡 🟡 🟡  db
 🟡 🔴 🔴 🔴 🟡 🟡 🟡 🟡 🔴 🔴 🔴 🔴  worker
─────────────────────────
 12:00                    14:00         now
```

This is a **colored dot timeline** (not a standard chart — custom component):
- X-axis: time (last 2 hours, bucketed into 5-min intervals)
- Y-axis: each service
- Dots: colored by health status at that interval
- Click a dot to see the error that caused the degradation

## Required Backend Fields

**Per service:**
`name`, `status` (healthy|degraded|down), `uptime_pct`, `total_requests`, `error_rate`, `avg_latency`, `p95_latency`, `p99_latency`, `last_seen`, `request_volume_timeseries[]`, `error_rate_timeseries[]`, `latency_timeseries[]`

**Per service health event:**
`timestamp`, `service_name`, `status`, `error_id` (linkable), `duration_minutes`
